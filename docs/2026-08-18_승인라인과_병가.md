# 2026-08-18 작업 기록 — 승인 라인(부서장)과 병가 버튼

마이그레이션 `202608180005_approval_line.sql`. 회귀 테스트 L 구간 26개를 더해 **195개**가 됐다.

사용자 결정 세 가지로 시작했다: "승인 라인은 그냥 부서장이 하는 걸로, 사업장은 그냥 한 곳,
병가 버튼 만들자."

---

## 1. 부서장을 무엇으로 정하는가

0004에서 **"직급은 권한이 아니다"**라고 그어 놓은 선이 있었다. 여기서 '부장이면 부서장'으로
이어 붙이면 그 선이 그날로 무너진다. 그래서 관리자가 부서마다 부서장을 **사람으로 직접 지정**한다
(`org_departments.head_user_id`). 직급 테이블은 이 결정에 전혀 관여하지 않는다.

권한은 누가 줬는지 화면에서 항상 보여야 한다. 직급에서 유도하면 "왜 이 사람이 남의 근태를
보지?"에 대한 답이 여러 단계를 거쳐야 나온다.

### 부서장이 할 수 있는 것 / 없는 것

| | |
|---|---|
| 할 수 있다 | 자기 부서원의 근태 정정·재택·휴가 승인, 자기 부서원의 근무시간 조회 |
| 없다 | 부서·직급 만들기와 배정, 월 마감, 연차 부여, 공휴일, 근무 정책 — 전부 관리자 그대로 |

**근무시간 조회를 같이 연 이유**: 승인하려면 봐야 한다. 정정 요청만 보고 누르는 승인은
승인이 아니라 결재 도장이다. 다만 이건 남의 임금 자료를 보는 권한이 넓어지는 변경이라,
테스트에서 '못 보는 것'을 '보는 것'보다 더 많이 확인했다.

### 자기 기록의 정정은 여전히 스스로 승인하지 못한다

부서장이 자기 출퇴근 시각을 스스로 고칠 수 있으면 이 시스템 전체가 뜻을 잃는다.
기존 '본인 승인 금지'를 그대로 뒀고, L-9가 이걸 지킨다. 이 파일에서 가장 중요한 케이스다.

## 2. 함수 전문을 다시 쓰지 않고 **DB가 자기 정의를 고치게** 했다

`get_attendance_summary`의 라이브 정의를 읽어 보니 **마이그레이션 파일과 달랐다.**
파일(0011)에 있는 주석 한 줄이 DB에는 없었다. 0008의 `isRemote`와 같은 일이 또 있는 것이고,
이 상태에서 파일 내용을 붙여넣었다면 **DB에만 있던 변경이 조용히 날아갔을 것이다.**

그래서 이렇게 했다:

```sql
create or replace function public.__patch_function(sig text, anchor text, replacement text) ...
  src := pg_get_functiondef(sig::regprocedure);
  hits := (length(src) - length(replace(src, anchor, ''))) / length(anchor);
  if hits <> 1 then raise exception '치환 지점이 1곳이 아닙니다(%곳)', hits; end if;
  execute replace(src, anchor, replacement);
```

DB가 자기 정의를 읽어 해당 한 줄만 바꿔 다시 만든다. 치환 지점이 정확히 1곳이 아니면
예외를 던지고 멈춘다 — **조용히 아무것도 안 하는 것보다 시끄럽게 실패하는 편이 낫다.**
작업이 끝나면 헬퍼는 지운다.

이 방식으로 함수 7개를 고쳤다: `get_attendance_summary`, `list_leaves`, `list_remote_work`,
`list_commute_corrections`, `review_commute_correction`, `review_remote_work`, `review_leave`.

새로 만들 함수(`is_my_department_member`, `can_review_member`, `list_org` 등)는 평소처럼 전문을 썼다.

## 3. 한 글자 차이로 새는 자리 — L-6

부서원까지 넓히는 조건을 이렇게 썼다:

```sql
and (scope is null or r.user_id = scope
     or (scope = auth.uid()::text and public.is_my_department_member(target_workspace_id, r.user_id)))
```

`scope = auth.uid()::text`라는 단서가 핵심이다. 이게 없으면 **부서장을 겸한 관리자가 집계에서
한 사람을 골라 볼 때 자기 부서원이 통째로 딸려 나온다.** 관리자는 `scope`에 고른 사람이 들어가고
일반 구성원은 자기 자신이 들어가므로, 이 단서가 "자기 자신으로 좁혀진 경우에만 넓힌다"를 뜻한다.

L-6이 이 케이스다. 처음 쓸 때 빠뜨렸다면 테스트가 아니라 운영에서 발견했을 종류의 버그다.

## 4. 목록 함수 두 가지 모양

- `list_remote_work` / `list_leaves` / `get_attendance_summary` — 원래 `scope`로 거르는 모양.
  위의 한 줄만 넓혔다.
- `list_commute_corrections` — 원래 **관리자만 열 수 있고** 행 단위 필터가 없었다.
  문을 '관리자 또는 부서장'으로 열고, 대신 행 필터를 새로 넣었다. 문만 열고 필터를 안 넣었으면
  부서장이 전사 정정 요청을 다 봤을 것이다.

## 5. 병가 버튼

DB(`commute_records.type`)와 `lib/attendance.ts`는 처음부터 `'sick'`을 받고 있었고
**UI에만 버튼이 없었다.** 조퇴/휴가 2열을 3열로 바꾸고 그 사이에 넣었다.

### 병가는 자기신고로 뒀다 (휴가와 다르게)

휴가는 승인제로 바꿨는데(0002) 병가는 그러지 않았다. 아파서 못 나오는 건 그날 아침에 벌어지는
일이라, 승인을 기다려야 기록할 수 있으면 **기록 자체가 늦어진다.** 연차를 깎지도 않는다.
잘못 눌렀으면 근태 정정 요청으로 바로잡는다.

규칙: 하루 한 번, 휴무일엔 불가, **퇴근한 뒤에는 불가**(그날은 이미 근무한 날로 기록됐다 —
일하다 아파서 나가는 건 조퇴다).

3열로 바꾸면서 각 버튼에 `min-w-0`과 `truncate`를 넣었다. 이 저장소에는 grid 아이템에
`min-w-0`이 없어서 모바일에서 박스가 넘쳤던 이력이 있다(8/6).

## 6. 사업장은 한 곳으로 확정

"사업장 여러 곳"은 확장 과제로 미뤄 뒀던 것인데(2026-08-17), 이번에 **정식으로 범위에서 뺐다.**
`work_policies`가 워크스페이스당 1행인 지금 구조를 그대로 간다.

## 알려진 한계

- **관리자 화면을 브라우저로 눌러 보지 못했다.** 로그인 뒤에 있고 계정 정보가 없다.
  타입·린트·빌드 통과, DB는 L 구간 26개로 검증. 화면 동작은 사용자 확인이 필요하다.
- 부서장이 **자기 재택·휴가는 스스로 승인할 수 있다.** 기존에 관리자에게 허용돼 있던 것과
  같은 규칙을 그대로 물려받았다(근태 정정만 금지). 목록에 `selfApproved`로 표시된다.
  구성원이 늘면 다시 볼 항목이다.
- 한 사람이 여러 부서의 부서장인 경우는 판정 함수가 `exists`라 그대로 맞지만, 화면에서
  "내 부서"를 하나로 보여 주지는 않는다.
- 부서장에게는 근무 정책 화면이 그대로 보인다(집계 카드 안에 있음). 저장은 서버가 막는다.
