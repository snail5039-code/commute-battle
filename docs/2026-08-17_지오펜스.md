# 2026-08-17 작업 기록 — 출근 위치 인증 (지오펜스)

마이그레이션 `202608170009_geofence.sql`. 근태 시스템에 남아 있던 마지막 큰 구멍이었다 —
사무실 출근에 위치 검증이 없어서 집에서도 출근 버튼이 눌렸다.

---

## 1. 설계안을 하나 고쳤다 — 검증 시점

`SETUP.md`에 남겨둔 설계안은 "`attendance_start`가 위치를 받아 판정"이었는데, 코드를 읽어 보니
이게 틀렸다. `attendance_start`는 **집에서 출발하는 순간**이다(`start_time`=출발, `end_time`=도착).
여기서 사업장 반경을 검사하면 "집이 회사 근처인가"를 보게 된다.

근무시간 산정(`202608170007`)이 실제로 쓰는 시각은 두 개뿐이다.

| 값 | 어디서 오나 | 검증이 붙는 RPC |
|---|---|---|
| 근무 **시작** | 출근(`commute`) 기록의 **도착** 시각 (`end_time`) | `attendance_finish` |
| 근무 **종료** | 퇴근(`return`) 기록의 **출발** 시각 (`start_time`) | `attendance_start` |

그래서 이 두 지점에만 검증을 걸었다. 반대쪽 두 지점 — 출근의 '출발'(집을 나서는 순간)과
퇴근의 '도착'(집에 들어가는 순간) — 은 사업장 밖이 정상이라 아예 좌표를 보내지 않는다.

**퇴근 출발을 함께 검증한 이유**: 여기를 비워두면 집에 도착해서 퇴근을 눌러 근무시간을
이동시간만큼 늘릴 수 있다. 출근만 막는 건 반쪽짜리다.

## 2. GPS가 실패하면 막지 않고 '미인증'으로 남긴다

사용자 결정. 터널·건물 안·권한 거부로 **현장에서 출근을 못 하는 사고가 더 크다**고 봤다.
차단하면 그날 근태가 통째로 비고, 정정 요청으로만 복구된다.

`commute_records`에 판정 결과를 남긴다.

- `location_verified` — `true` 반경 안 / `false` 미인증(관리자 확인 대상) /
  **`null` 검증 대상 아님**(사업장 좌표 미설정, 재택, 워크스페이스 없는 개인 기록)
- `location_status` — `verified` `out_of_range` `low_accuracy` `unavailable` `denied` `no_policy`
- 좌표·정확도·거리·판정 시각

세 값(true/false/null)을 쓴 게 핵심이다. "인증 안 됨"과 "인증할 필요가 없음"을 한 컬럼에
섞으면 집계에서 재택과 미인증을 구분할 수 없다.

## 3. 판정은 전부 서버에서

브라우저는 좌표와 정확도만 보낸다. 거리 계산과 반경 비교는 `attendance_location_check`
(security definer)가 하고, 이 함수는 **anon·authenticated 모두에게 EXECUTE를 회수**했다.
직접 호출하게 두면 "지금 여기가 반경 안인가"를 반복 조회해서 사업장 좌표를 역추적할 수 있다.
거리 계산 `geo_distance_m`(하버사인)도 같이 잠갔다 — PostGIS는 켜지 않았다.

클라이언트가 보내는 `location_denied`는 '권한 거부'와 '신호 없음'을 구분하는 표시일 뿐이고,
어느 쪽이든 결과는 미인증으로 같다. 이 값으로 판정을 바꿀 수는 없다.

정확도 게이트를 따로 뒀다. `accuracy > location_accuracy_m`(기본 150m)이면 거리가 반경 안이어도
`low_accuracy`로 남긴다 — 오차 400m짜리 좌표가 200m 반경 안에 찍혔다는 건 근거가 되지 않는다.

**개인정보**: 지오펜스를 쓰지 않는 워크스페이스(`no_policy`)에서는 좌표를 아예 저장하지 않는다.
판정에 쓰지도 않을 위치를 보관할 이유가 없다.

## 4. 화면

- **관리자** (`components/admin/OfficeLocationPicker.tsx`): /admin → 근무 정책에 사업장 지도.
  주소 검색·지도 클릭·'현재 위치'로 좌표를 정하고, 허용 반경 원이 지도에 그려진다.
  '위치 인증 끄기'로 좌표를 비우면 검증이 꺼진다(기본값이 이 상태다).
- **집계** (`AttendanceReport.tsx`): '위치 미인증' 요약 타일, 미인증 건 경고 배너(구성원·날짜·최대 거리),
  일별 표의 '위치' 열, CSV의 '위치인증' 열. 사업장 미지정이면 안내 문구가 뜬다.
- **직원**: 출근 도착 후 대시보드에 사유가 담긴 배너(`CommuteButton.tsx`), 퇴근 출발은
  경로 모달에서 확인을 받고 넘어간다(`RouteModal.tsx`). 인증에 성공하면 아무것도 뜨지 않는다.

## 5. 검증 (롤백되는 DO 블록, 실제 RPC · 실제 계정)

서울시청을 사업장(반경 200m)으로 두고 8케이스. 마지막에 예외를 던져 전부 롤백했다.

| 사례 | 결과 |
|---|---|
| 퇴근 출발 · 반경 안 (정확도 20m) | `verified` · 29.5m |
| 퇴근 출발 · 반경 밖 | `out_of_range` · 1111.9m |
| 퇴근 출발 · 위치 권한 거부 | `denied` · 좌표 미저장 |
| 퇴근 출발 · 정확도 400m (반경 안) | `low_accuracy` |
| 출근 **출발** | 검증 안 함 (`null`) |
| 출근 **도착** · 반경 안 | `verified` · 13.6m |
| 출근 **도착** · 집에서 누름 | `out_of_range` · 21.4km |
| 사업장 좌표 미설정 | `no_policy` · 좌표 미저장 |

권한도 확인했다 — `geo_distance_m`/`attendance_location_check`는 anon·authenticated 모두 실행 불가,
나머지 RPC는 authenticated만 실행 가능.

지도 피커는 임시 페이지로 로그인 가드를 우회해 브라우저에서 확인했다(확인 후 되돌림):
지도 타일 로드, 반경 800m↔200m 변경 시 원 크기 반영, 주소 검색으로 좌표 이동, '위치 인증 끄기'로
원 제거 + '미설정' 표시.
