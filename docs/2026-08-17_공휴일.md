# 2026-08-17 작업 기록 — 공휴일 달력

마이그레이션 `202608170011_holidays.sql`. 휴일이 토·일 고정이라 광복절에 일해도 휴일근로 가산이
안 잡히던 문제를 없앴다.

## 1. 공휴일 날짜를 코드에 넣지 않았다

설날·추석·부처님오신날은 음력이라 해마다 바뀌고, 대체공휴일 규칙도 얽혀 있다. 기억으로 채워 넣으면
틀렸을 때 그게 그대로 임금 계산에 들어간다. 그래서 **출처를 밖에 두고 가져오는 구조**로 만들었다.

입력 경로 세 가지. 저장은 셋 다 같은 RPC(`save_work_holidays`)를 쓴다 — 파싱만 다르다.

| 경로 | 언제 쓰나 | 특징 |
|---|---|---|
| 공공데이터 API | 기본 | 연도만 바꿔 호출. 음력·대체·임시공휴일 다 옴 |
| CSV 업로드 | 키가 없거나 다른 기관 파일을 쓸 때 | 정적 파일이라 갱신은 사람 몫 |
| 직접 추가 | 창립기념일, 단체 연차 | 회사마다 다른 휴일 |

**API vs CSV는 경쟁이 아니라 보완이다.** CSV는 키 없이 지금 당장 쓸 수 있지만 정적 파일이라
내년에 누군가 다시 받아야 하고, API는 키가 필요하지만 연도만 바꾸면 항상 최신이다. 둘 다 넣었다.

## 2. API 확인 결과 (한국천문연구원 특일 정보)

- 2027년까지 나온다 (자료마다 "1년치만"이라고 하는데 실제로는 더 나왔다)
- 2026년 22건, 2027년 24건

받은 데이터에서 눈여겨볼 것:

### 키 관련 함정

data.go.kr은 키를 **Encoding / Decoding** 두 가지로 준다. 코드에서 `URLSearchParams`로 인코딩하므로
**Decoding 키**를 넣어야 한다. Encoding 키를 넣으면 `%2B`가 이중 인코딩돼 인증이 깨진다.
(실측해 보니 이 키는 `%`가 없는 Decoding 키였고 양쪽 다 통과했지만, 규칙은 Decoding으로 못박았다.)

## 3. 데이터 모델

`work_holidays(workspace_id, holiday_date, name, source)` — 워크스페이스당 한 행씩.

같은 공휴일이 회사마다 중복 저장되지만, 그 대신 **"우리 회사는 그날 정상 근무한다"를 그 행만 지워서**
표현할 수 있다. 전역 테이블 + 회사별 예외 테이블보다 단순하고, 이 규모에서 중복은 문제가 아니다.

다시 불러올 때 `overwrite=false`를 써서 **이미 등록된 날짜는 건드리지 않는다.** 관리자가 손본 이름과
자체 휴일이 API 재호출로 덮어써지면 안 되기 때문이다.

집계(`get_attendance_summary`)에서 휴일 판정만 바꿨다.

```sql
-- 전: extract(isodow from date) >= 6
-- 후: extract(isodow from date) >= 6 or exists (select 1 from hol where hol.holiday_date = date)
```

나머지 계산은 그대로다. 휴일이면 근무시간이 휴일근로로 잡히고 지각·조기퇴근을 따지지 않는 로직이
이미 있었다. 일별 결과에 `holidayName`을 얹어 리포트와 CSV에 휴일 이름이 나온다.

## 4. 검증

### CSV 파서 (브라우저, 8케이스)

실물 파일을 아직 못 봐서 **헤더 이름에 기대지 않는** 파서로 만들었다 — 어느 열이 날짜처럼 생겼는지
세어서 고른다. 확인한 것:

표준형 / `2026.10.03` 점 구분 / `20261225` 8자리 / **날짜 열이 두 번째여도 자동 감지** /
따옴표 안의 쉼표 / 중복 날짜 제거 / 날짜 열이 없으면 빈 결과 / **EUC-KR 디코딩**(한글 안 깨짐) /
`2026-02-30` 같은 없는 날짜 거부.

### SQL 회귀 테스트 (13케이스 추가, 총 67개)

공휴일 등록 → 그날이 휴일근로 750분·지각 0으로 바뀌는지, 삭제하면 지각 30분으로 돌아오는지,
`overwrite=false`가 기존 이름을 지키는지, 일반 구성원이 저장하면 막히는지, anon에게 닫혀 있는지.

### 테스트 하네스에서 버그 두 개가 나왔다

1. **`fails := fails || '문자열'`이 배열 캐스팅 오류로 죽는다.** 리터럴 타입이 모호해서
   Postgres가 `text[] || text[]`로 해석한다. 지금까지 전부 통과해서 그 분기가 한 번도 실행되지
   않아 안 보였다 — 처음 실패하는 순간 터졌다. 70곳을 `array_append`로 바꿨다.
2. **구간끼리 픽스처를 물려받고 있었다.** C·D 구간이 기록을 지우는데 G가 A·B의 픽스처를 기대해서,
   G 로직은 멀쩡한데 빈 데이터를 보고 실패했다. 구간마다 자기 기록을 넣도록 고쳤다.

둘 다 파일 머리말에 "케이스 추가할 때 지킬 것"으로 적어 뒀다.

## 5. 곁다리 — "통계에서 제외"가 승인제여야 하지 않나

사용자가 캘린더 스크린샷을 보고 물었다. 확인해 보니 **승인은 필요 없다.**

이 버튼은 `localStorage` 기반이고 `/stats`(개인 이동 통계·게임 요소)만 가린다.
임금 근거가 되는 `get_attendance_summary`는 서버에서 `commute_records`를 직접 읽으므로 영향이 0이다.
기록을 지우는 것도 아니다.

다만 **걱정한 것 자체가 UI 잘못**이다. 휴지통 아이콘 + "통계에서 제외"라는 문구는 삭제처럼 읽히고,
설명은 누른 뒤에만 나왔다. 고쳤다.

- 아이콘 `Trash2` → `EyeOff`, 문구 "내 통계에서 숨기기" / "내 통계에 다시 표시"
- 설명을 **누르기 전에도** 항상 표시: "이 기기의 내 통계 화면에서만 가려집니다. 기록 원본과
  근태 집계·급여에는 그대로 반영됩니다."

## 알려진 한계

- **공휴일에도 출근 버튼이 그대로 눌린다.** 집계에는 휴일로 반영되지만 버튼 상태는 아직 기기 설정
  기준이다. 휴일 출근이 실제로 있을 수 있어 막지 않았지만, 안내는 없다.
- 매년 초에 관리자가 "불러오기"를 눌러야 한다. 자동 갱신은 없다.
- 사업장이 여러 곳이면 공휴일도 워크스페이스마다 따로 넣어야 한다(지금은 워크스페이스가 하나라 무의미).
- CSV 파서는 합성 데이터로만 검증했다. 실제 공공데이터 파일로 한 번 돌려봐야 한다.
