# 2026-08-18 작업 기록 — 휴가 회귀 테스트 편입 (85 → 126)

지난 세션에 휴가(`202608180002_leave.sql`)를 만들면서 19케이스를 **별도로** 돌려 검증하고
`supabase/tests/attendance.sql`에는 넣지 못한 채 남겨 뒀다. 별도로 돌린 검증은 다음에 아무도
다시 돌리지 않으므로 사실상 없는 것과 같다. 이번에 I 구간으로 편입했다.

결과: **통과 126 / 실패 0**. (기존 85 + 휴가 41)

## 1. 왜 지난번에 편입하지 못했나 — 날짜 때문이다

이 파일의 다른 구간(A~H)은 전부 **2020년 6월 고정일**을 픽스처로 쓴다. 요일이 고정되어야
휴일·주말 판정을 검증할 수 있기 때문이다.

그런데 `request_leave`는 이렇게 막고 있다:

```sql
if from_date < today - 31 or from_date > today + 365 then
  raise exception '신청 가능한 날짜 범위를 벗어났습니다.';
```

지난 일을 소급 신청해 잔여를 맞추지 못하게 하는 제한이다. 이 제한이 있는 한 2020년 날짜로는
휴가를 **한 건도 신청할 수 없다**. 그래서 I 구간만 실행 시점 기준 상대 날짜를 쓴다.

```sql
lv_mon := (today + 7) - (extract(isodow from (today + 7))::int - 1);   -- 다음 주 월요일
if extract(year from lv_mon) <> extract(year from lv_mon + 11) then lv_mon := lv_mon + 14; end if;
```

둘째 줄이 필요한 이유: **연차 잔여는 연도별**(`leave_grants.year`)이다. 잡힌 2주가 해를 넘기면
부여와 사용이 서로 다른 해로 갈라져 잔여 검증이 무너진다. 연말에만 걸리는 문제라 그냥 두면
12월 말에 처음 터지고, 그때는 원인을 찾는 데 한참 걸린다. 그런 주가 잡히면 2주 민다.

이 교훈을 파일 머리말의 "케이스를 추가할 때 지킬 것"에 3번으로 넣었다 —
**날짜를 검사하는 RPC를 덮을 땐 그 RPC가 받는 날짜 범위부터 볼 것.**

## 2. 무엇을 덮었나 (I-1 ~ I-24, 검사 41개)

| 묶음 | 내용 |
|---|---|
| 부여 | 일반 구성원은 부여 불가 / 부여하면 잔여에 그대로 보임 |
| 일수 계산 | 월~금에서 공휴일 하나 빼면 4일 / 주말만이면 0일 |
| 신청 거부 | 잔여 초과 · 주말만 · 종료일 역전 · 여러 날 반차 · 알 수 없는 종류 · 사유 없음 · 40일 전 소급 · 기간 겹침 |
| 신청 성공 | 공휴일 낀 한 주가 4일로 잡힘 / 반차는 0.5일 |
| 잔여 | 대기 중엔 `pendingDays`만 오르고 잔여는 그대로 → 승인 후에 깎임 |
| 승인 | 일반 구성원 승인 불가 / 근무일마다 휴가 기록 자동 생성(공휴일·주말 제외) / 재승인 불가 |
| 거절 | 상태만 바뀌고 기록은 안 생김 |
| 취소 | 승인된 건 취소 불가 / 남의 신청 취소 불가 |
| 충돌 | 그 기간에 출퇴근 기록이 있으면 승인 차단 |
| 격리 | 일반 구성원에게는 남의 휴가·잔여가 안 보임 |
| 권한 | 신청·승인·부여는 anon에게 닫힘, `leave_working_days`는 authenticated에게도 닫힘 |

**잔여가 언제 깎이는지**(I-13 → I-16)를 특히 붙잡아 뒀다. 신청만으로 깎이면 반려된 신청이
연차를 먹고, 승인해도 안 깎이면 초과 사용이 난다. 둘 다 임금 문제로 이어진다.

## 3. 편입하면서 확인한 것

- I 구간은 앞 구간(A~H)이 만들어 놓은 상태 위에서 돈다. 시작할 때 `commute_records`와
  `work_holidays`를 지워 자기 픽스처를 새로 깐다(파일 머리말 2번 규칙).
- `outsider`(일반 구성원)와 `admin2`(둘째 관리자)는 G·H가 이미 만들어 둔 것을 물려 쓴다.
  I 구간에서 다시 만들면 중복 삽입으로 죽는다.
- H가 2020-06을 마감했다 해제해 두지만, I가 쓰는 날짜는 다음 주라 서로 닿지 않는다.

## 4. 알아 둘 것

- **I 구간은 실행하는 날짜에 따라 픽스처 날짜가 달라진다.** 다른 구간처럼 고정되어 있지 않다.
  실패 메시지에 날짜가 안 찍히므로, I 구간이 깨지면 먼저 오늘이 며칠인지부터 볼 것.
- 마감된 달에는 휴가를 신청할 수 없다는 규칙(`request_leave`의 마감 검사)은 **덮지 못했다.**
  I 구간이 쓰는 날짜는 미래인데, 아직 끝나지 않은 달은 마감 자체가 안 되기 때문이다(H-1).
  마감 로직 자체는 H 구간 18개가 덮고 있다.
- 휴가 화면(`components/LeavePanel.tsx`)은 여전히 브라우저로 눌러 보지 못했다. DB 쪽은
  이제 회귀 테스트가 지키지만 화면 동작은 사용자 확인이 필요하다.
